## Summary

Eliminate validation target leakage, in-sample calibration evaluation, greedy OOF hill-climbing, test pseudo-label sharpening, and arbitrary test prevalence scaling across Stages 2–5.

This implementation plan directly operationalizes the detailed plan defined in [`docs/superpowers/plans/2026-09-29-leak-free-cv-pipeline.md`](../../docs/superpowers/plans/2026-09-29-leak-free-cv-pipeline.md).

## Technical Context

**Language/Version**: Python 3.10+  
**Primary Dependencies**: LightGBM, CatBoost, XGBoost, Scikit-learn, SciPy, Pandas, NumPy  
**Storage**: Parquet / NumPy NPZ (`checkpoints/`, `submissions/`)  
**Testing**: pytest  
**Target Platform**: Linux server / Kaggle / local environment  
**Project Type**: Machine Learning Cross-Validation & Ensembling Pipeline  
**Performance Goals**: 10-fold nested feature screening in <30s total; zero target leakage across folds  
**Constraints**: Zero changes to the competition metric definition ($0.40 \cdot \text{AUC} + 0.60 \cdot (1 - \text{LogLoss} / 0.595)$); all probabilities strictly bounded in $[0.0020, 0.9980]$  
**Scale/Scope**: 40,000 training observations, 30,000 test observations, 200+ engineered features, 5 GBDT architectures, 5 pipeline stages  

## Global Constraints

- Competition metric definition in `src/metrics.py` ($0.40 \cdot \text{AUC} + 0.60 \cdot (1 - \text{LogLoss} / 0.595)$) MUST NOT be altered.
- All probability outputs must remain bounded within $[0.0020, 0.9980]$ (`FLOOR`, `CEIL`).
- All feature selection and scaling must observe ONLY outer training partitions ($X_{tr}, y_{tr}$).
- Calibrated out-of-fold predictions must strictly be generated by models that did not see those validation samples during calibration fitting.
- Test predictions must be computed as the fold-ensemble average of the fold models.
