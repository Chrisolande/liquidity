# Feature Specification: Leak-Free Cross-Validation & Calibration Pipeline

**Feature Branch**: `001-fix-cv-leakage`

**Created**: 2026-09-29

**Status**: Draft

**Input**: User description: "Fix CV leakage, fold cache bug, and calibration issues across the modeling pipeline (Stage 2–5) to align local validation with real generalization performance."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Fold-Isolated Supervised Feature Selection (Priority: P1)

As a quantitative researcher evaluating model performance, I need supervised feature screening to occur strictly within each training fold, so that validation metrics accurately reflect generalization rather than memorized target patterns from holdout splits.

**Why this priority**: Global supervised feature selection before cross-validation exposes validation fold target labels to the feature selector, creating target leakage that artificially inflates validation metrics and causes severe performance drops on unseen evaluation sets.

**Independent Test**: Can be tested independently by running cross-validation with synthetic or permuted target labels in the validation folds to verify that feature subsets selected on training partitions never correlate with validation fold outcomes.

**Acceptance Scenarios**:

1. **Given** a partitioned training dataset with distinct train and validation folds, **When** supervised feature screening is initiated, **Then** feature ranking and selection criteria are computed strictly using only the training split records and labels without observing validation records.
2. **Given** multiple outer cross-validation folds, **When** the pipeline iterates through each fold, **Then** each fold independently determines its active feature subset based solely on that fold's training slice.
3. **Given** a complete cross-validation run with fold-isolated selection, **When** out-of-fold performance is evaluated, **Then** the reported metric is an unbiased, leakage-free estimate of generalization capability.

---

### User Story 2 - Resilient Fold Data Caching and Metadata Retention (Priority: P1)

As a pipeline operator running diverse model architectures across identical cross-validation splits, I need cached fold partitions to reliably retain all required feature metadata across sequential model executions, so that downstream models execute without missing-attribute failures.

**Why this priority**: When sharing pre-partitioned folds across multiple model architectures, partial initialization of categorical column metadata causes runtime execution crashes or incorrect column drops whenever a cache hit occurs.

**Independent Test**: Can be tested independently by running two or more sequential model architectures over a shared fold cache and verifying that categorical columns and required metadata are identical and fully resolved in both the initial population run and subsequent cache retrieval runs.

**Acceptance Scenarios**:

1. **Given** pre-partitioned data stored in a fold cache, **When** a subsequent model architecture queries the cache for a fold partition, **Then** both the partitioned dataset and the associated active column metadata (such as categorical identifiers) are fully accessible.
2. **Given** a fold partition loaded from cache, **When** model-specific feature filtering occurs, **Then** all categorical features designated in the original schema remain valid and properly referenced without relying on conditional branch execution history.

---

### User Story 3 - Strictly Cross-Fitted Probability Calibration (Priority: P1)

As a risk analyst relying on calibrated probabilities, I need probability calibrators to be cross-fitted so that out-of-fold calibration metrics are evaluated strictly on holdout data rather than fitted and scored in-sample.

**Why this priority**: Fitting a post-processing calibrator on the entire out-of-fold prediction set and then scoring those same predictions produces an in-sample validation estimate, misrepresenting true probability reliability and misaligning local evaluations with production test sets.

**Independent Test**: Can be tested independently by verifying that every out-of-fold prediction passed to the scoring metric was generated by a calibrator that did not include that sample in its fitting set.

**Acceptance Scenarios**:

1. **Given** out-of-fold raw model predictions and corresponding ground-truth labels, **When** probability calibration is applied, **Then** calibration parameters are fitted strictly on out-of-fold training sub-splits and applied out-of-sample to validation sub-splits.
2. **Given** the final assembled calibrated out-of-fold predictions, **When** pipeline validation metrics are computed, **Then** the evaluated scores represent 100% out-of-sample calibrated estimates.
3. **Given** test dataset inference, **When** applying the fitted calibrators, **Then** predictions are calibrated using an ensemble or average of the cross-fitted calibration models.

---

### User Story 4 - Unbiased Ensemble Model Selection and Optimization (Priority: P2)

As an ML engineer assembling an ensemble of diverse prediction streams, I need ensemble weighting and model search procedures to be protected against over-optimizing on out-of-fold noise, so that the selected ensemble remains robust on unseen test data.

**Why this priority**: Aggressive greedy search or metric maximization directly against a single fixed out-of-fold prediction set across many candidate streams overfits validation noise, creating false gains that fail to transfer to leaderboard or production environments.

**Independent Test**: Can be tested independently by running ensemble candidate selection on nested validation splits or bounded regularization and confirming that candidate selection does not exploit label noise in the primary validation split.

**Acceptance Scenarios**:

1. **Given** multiple candidate prediction streams, **When** ensemble weights or component selections are determined, **Then** the optimization is constrained, regularized, or nested such that weights are not fitted to exploit sample-level validation noise.
2. **Given** an ensemble candidate search, **When** an ensemble does not demonstrate statistically meaningful validation improvement over a simpler baseline, **Then** the pipeline defaults to the parsimonious baseline rather than selecting an overfitted combination.

---

### User Story 5 - Streamlined Single-Stage Calibration Hierarchy (Priority: P2)

As a pipeline architect, I need a simplified, single-stage calibration workflow rather than repeated intermediate calibration stages, so that probability distortion and compounding estimation errors are eliminated.

**Why this priority**: Repeatedly calibrating predictions at intermediate stages (base model -> intermediate calibrator -> meta-stacker -> final calibrator) introduces compounding estimation drift and complicates error tracking.

**Independent Test**: Can be tested independently by comparing final probability calibration quality and discrimination between a single-stage end-of-pipeline calibration versus multi-stage repeated calibrations.

**Acceptance Scenarios**:

1. **Given** predictions from multiple base learners, **When** passing them to meta-learning or ensembling layers, **Then** raw predictions or consistent logit representations are utilized without redundant intermediate calibration passes.
2. **Given** the final combined meta-ensemble output, **When** probability calibration is required, **Then** calibration is performed as a single unified cross-fitted step immediately preceding final evaluation and submission generation.

---

### Edge Cases

- **Constant or Single-Class Folds**: How does the system handle a fold where a screened feature has zero variance or a rare category is absent? The system must fall back to global safe defaults or ignore zero-variance columns within that fold without crashing.
- **Empty Feature Selection**: What happens if supervised screening within a fold fails to select the target number of features due to strict thresholds? The system must ensure guaranteed domain features and baseline indicators are preserved as a fallback floor.
- **High Dimensionality per Fold**: What happens when different folds select slightly different subsets of features during training? Test inference must project each fold's trained model only onto the specific features selected for that fold.
- **Identical Prediction Streams in Ensembling**: What happens if two candidate models produce near-identical predictions during stacking or weighting? The system must apply regularization to avoid degenerate or collinear weight solutions.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: The system MUST enforce strict isolation of outer validation folds such that supervised feature selection algorithms never access validation fold features or labels.
- **FR-002**: The system MUST execute feature screening independently for each cross-validation fold using exclusively the training partition of that fold.
- **FR-003**: The system MUST guarantee that persistent baseline and domain-critical features are retained across all fold-specific feature sets.
- **FR-004**: The system MUST maintain complete feature metadata (including column schemas, data types, and categorical designations) alongside fold data in any shared partitioning cache.
- **FR-005**: The system MUST ensure that cached fold data retrieval functions identically and deterministically regardless of the execution order of consuming model architectures.
- **FR-006**: The system MUST fit probability calibrators strictly on designated training subsets and evaluate calibration quality exclusively on out-of-sample validation records.
- **FR-007**: The system MUST produce test set predictions using an ensemble aggregation of the cross-fitted calibration models corresponding to each training fold.
- **FR-008**: The system MUST eliminate redundant intermediate calibration steps between base model outputs and meta-stacking inputs, reserving calibration for the final unified stage unless empirical out-of-fold validation demonstrates measurable benefit.
- **FR-009**: The system MUST restrict greedy ensemble optimization (such as unconstrained metric climbing) from directly fitting against the identical evaluation split used to score the final pipeline.
- **FR-010**: The system MUST recalculate and record clean, uncorrupted baseline out-of-fold validation metrics for all model streams following the removal of data leakage.

### Key Entities *(include if feature involves data)*

- **Fold Partition**: A split of the source dataset into disjoint training, validation, and holdout record sets, maintaining stratified label proportions.
- **Fold Feature Mask**: The set of column identifiers selected specifically for an individual training fold partition by the supervised screening process.
- **Fold Partition Cache**: A shared repository storing materialized fold splits and associated column metadata to eliminate duplicate processing across model architectures.
- **Out-of-Fold (OOF) Prediction Set**: A consolidated set of model predictions where each sample was predicted exclusively by a model that did not include that sample in its training data.
- **Cross-Fitted Calibrator**: A collection of calibration transformations fitted on training fold subsets to generate unbiased out-of-sample calibrated probabilities.
- **Meta-Stacking Dataset**: A dataset constructed from out-of-fold base model predictions used to train higher-level ensemble combination weights.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 100% of supervised feature selection operations are executed strictly within outer training partitions, with zero validation fold data exposure across all cross-validation runs.
- **SC-002**: 100% of out-of-fold calibration evaluations are performed on records held out from the calibrator fitting process.
- **SC-003**: The discrepancy between cross-validation scores and unseen holdout evaluation scores is reduced to within normal statistical variance (absolute discrepancy under 0.015).
- **SC-004**: Zero runtime errors or missing column exceptions occur when executing sequential model architectures against the shared fold partition cache.
- **SC-005**: 100% of candidate model streams and ensemble configurations can be traced to clean, leakage-free validation metrics.
- **SC-006**: Total end-to-end pipeline execution time with fold caching and nested screening remains within 1.25x of the baseline pipeline execution duration.

## Assumptions

- The primary training dataset contains sufficient sample volume (e.g., ~40,000 samples) such that 10-fold cross-validation provides stable, representative training partitions (~36,000 samples each) for nested feature selection.
- Domain-critical and guaranteed features identified in prior exploratory analysis remain universally applicable across all training folds.
- Target distributions are sufficiently balanced across folds using stratified partitioning to ensure calibrators converge reliably in each fold.
- The pipeline evaluation metric is evaluated on probability outputs where probability calibration directly impacts log-loss or threshold-dependent competition scores.
- Test set inference will average predictions across all fold models, with each fold model applying its respective fold-specific feature mask and fold calibrator.
